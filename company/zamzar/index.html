企业档案 / Zamzar

两兄弟拿 £1,000 起步、£10 做营销，20 年后还在靠一个小工具做生意。

Chris 和 Mike Whyley 两兄弟遇到文件格式转换麻烦，既不愿购买复杂软件，也不想为打开一个文件反复安装工具。2006 年，他们推出能在浏览器里操作的转换网站，起初提供 150 种转换类型。网站获得科技媒体报道，直到 2007 年 11 月推出订阅方案，官网才记录第一位付费客户。二十年后，他们仍然保持小团队运转。

第一年，他们几乎没钱做推广，先把工具做得真的有用

Zamzar 官网回顾：2006 年创始资金约 £1,000，最初营销预算只有 £10。产品解决无须下载安装软件即可转换不同格式的文件问题。官方 2016 年回顾记载，网站上线后获得 TechCrunch、Wired、Lifehacker、BBC 的报道；Wired 2006 年 11 月的原始文章独立证明当时确有免费转换服务。不能把媒体报道写成现金付费或转化率。

用户先来，付款却等了十三个月

二十年没有引入风投，靠不断扩展使用场景继续经营

第一批真正的客户在哪里？

首位付费客户发生在 2007 年 11 月，是官网明确列出的里程碑。但目前无法确认这位客户是谁、从哪个网站点击而来、支付金额及订阅期限，所以不能把当年 Wired 或 TechCrunch 的报道直接认作第一单的获客渠道。可以确定的是免费工具先运营约一年后才引入订阅收费。

哪些可以借鉴？

先做一个不用学习、不必安装的在线小工具，直接完成某个真实的痛苦任务；把免费体验做得足够好，让搜索、媒体与口碑自然发现它。只有确认有人持续使用之后，再测试大文件、批量处理、保存历史或 API 等具有明确付费理由的功能。

哪些不能照搬？

2006 年的搜索与媒体环境和 2026 年完全不同；今天的文件处理还涉及安全隐私、版权、算力成本、恶意文件扫描和大模型工具竞争。£10 只是创始人自述的营销支出，不能据此推算获客成本或做保证回报的商业预测。

怎样做一个小规模验证？

先只选一种非常明确的文件格式转换或处理痛点，做一个浏览器里能在 30 秒内完成的原型；征得同意邀请 15 位真实用户测试，记录任务成功率、重复使用意愿、对大文件或 API 的愿付价格。没有真实使用，不扩展到数百个工具。

必须说明的证据边界

7.66 亿是累计转换次数，5.5 亿是公司自述的累计使用人数，100 万/天是 API 请求次数；均不是付费用户数、营收或净利润。£10 是早期营销预算而不是获客成本。官方十周年“持续盈利”说法未经独立财务审计，2026 年收入、成本和净利润未知。

结论

值得学的是：从一个任何人都懂的痛点做起，先给足免费价值，慢慢建立自然使用与长期信任。最初 13 个月没收到钱，也不意味着这门生意不会成立。
